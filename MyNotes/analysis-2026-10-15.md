## 3. Documentation comments (Doxygen)

All comments that describe a file, class, function or member now use Doxygen's "light" form, which any documentation generator for C++ (Doxygen, clang-doc, Visual Studio's hover tips) understands:

```cpp
/// @file swapchain.h
/// @brief The swapchain: the images that are shown in the window. (Stage 7)
///
/// Longer explanation, as many /// lines as needed.

/// One-sentence summary; it becomes the brief description.
///
/// More detail after a blank /// line.
/// @param width, height  only where the name doesn't say it all
/// @return               only where useful
/// @throws std::runtime_error  when the function can throw
std::uint32_t choose_image_count(const vk::SurfaceCapabilitiesKHR& capabilities);

vk::SwapchainKHR chain;   ///< A member, documented after it with ///<
```

Rules we follow:
- `///` for documentation (what a thing is and how to use it). Plain `//` stays for teaching comments INSIDE functions (how and why this line works), which documentation generators ignore on purpose.
- The first sentence is the summary.
- `@param` / `@return` / `@throws` only where they add something.
- Checked by clang's `-Wdocumentation` (it warns, for example, about an `@param` naming a parameter that doesn't exist). That check is part of `tools\analyze.bat`.

Doxygen 1.18.0 and Graphviz 16.1.0 are installed in `C:\Users\gonza\Dev\Tools\`. The project's `Doxyfile` (in the project folder, every setting commented) turns the comments into HTML pages with include and call graphs: run `C:\Users\gonza\Dev\Tools\doxygen-1.18.0\doxygen.exe Doxyfile` and open `build-docs\html\index.html`. Its settings follow the tools thread's rules: `EXTRACT_ALL = NO` (so an undocumented declaration is reported, not silently included), every file has `/// @file` (otherwise Doxygen skips that file's free functions), and `WARN_AS_ERROR = FAIL_ON_WARNINGS` (any warning fails the run). The first run reported 7 warnings (parameters left out of an `@param` list, one undocumented helper); all fixed, now 0. Docs: https://www.doxygen.nl/manual/docblocks.html

One more rule learned the hard way: write one `@param` per parameter. `@param width, height` passes LLVM 19's check, but LLVM 23's `-Wdocumentation` rejects it (the analysis recheck found three).
